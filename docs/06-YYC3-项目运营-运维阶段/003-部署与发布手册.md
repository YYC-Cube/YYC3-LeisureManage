## 一、首次部署（已完成 2026-11-02；重放用）

1. **数据库**（Mac 主库机）：
   ```bash
   bash services/leisure-api/scripts/pg-prod-bootstrap.sh --host 127.0.0.1 --port 5433 --superuser yanyu
   DATABASE_URL="$DATABASE_URL_OWNER" pnpm --dir services/leisure-api exec prisma migrate deploy
   ```

## 二、版本发布（标准流）

```bash
# 1) 本机构建（Web）
cd apps/app-leisure-web && pnpm type-check && pnpm build
rsync -az --delete dist/ yyc3-33:/root/yyc3-leisure-edge/web/

# 2) 销售端 H5（API_BASE 内联）
cd apps/app-mp-artist && TARO_APP_API_BASE='https://lm.0379.pro/api/v1' pnpm build:h5
rsync -az --delete dist/ yyc3-33:/root/yyc3-leisure-edge/h5/

# 3) 后端（Mac 主实例）
cd services/leisure-api && pnpm build   # dist 更新 → launchd 自动拉起新进程? 否：launchd 不监听文件
kill $(launchctl list | grep leisure-api-prod | awk '{print $1}')   # KeepAlive 自动重启加载新 dist
```

- 发布窗口内静态即 rsync 即生效；后端重启 <2s（KeepAlive 拉起）
- NAS 备实例如需同步：rsync src → NAS → `docker-compose build api && up -d`

### HTML 入口禁缓存(2026-11-08 P0 事故修复)
- 边缘 nginx 已加 `/index.html`+`/m/index.html` no-cache(备份 bak-20261107-cache);**发布验证必查:`curl -sI https://lm.0379.world/ | grep cache-control` 必须返回 no-cache**——否则浏览器持旧 index 引用已删 hash chunk=懒加载 404(「表单/页面打不开」事故根因)。
- 观察项:rsync --delete 仍会删旧 assets;no-cache 后浏览器每次拿新 index → 恒引用现存 chunk ✓;若需零风险可改 rsync 不删 assets(--ignore-existing)另行评估。

### 发布验证注意(2026-11-07 坑)
- **web/H5 均为路由级懒加载分包**:页面代码在 `assets/m-chat-*.js` / H5 `chunk/N.js` 等分包(`index-*.js`/`app.js` 只是壳)。公网验证必须 `curl` 对应分包 grep 特征串,只 grep 壳文件会误判「发布未生效」。
- **构建≠生效**:dev/prod API 均为裸 `node dist/main.js`(无 --watch);构建后必须重启进程(launchd KeepAlive 机器 kill PID 即拉起)。
- **WS 现状(2026-11-07 修复)**:原生 ws 已挂 `/api/v1/ws/chat`(此前错挂 `/ws/chat` 与客户端错配,WS 从未连通一直静默轮询);边缘 nginx 仍无 Upgrade 头——生产前端自动回落轮询(体验不降级),Owner 启用边缘 WS Upgrade 后即升实时。

### WS 全链收口(2026-11-07 落地)
- 边缘 nginx.conf 增 `location /api/v1/ws/chat`(Upgrade 透传+读超时 1h;备份 nginx.conf.bak-20261107);Traefik 前置层默认透传 WS 无需配置;**公网 wss://lm.0379.world(lm.0379.pro 别名同配置)/api/v1/ws/chat 双域 101 握手实证**。
- 改动顺序=备份→容器内 `nginx -t`→`docker restart yyc3-leisure-edge`(单文件 bind mount 必须 restart 非 reload)→四链健康(healthz/web/h5/API 401)→wss 握手。
- 生产实时化现状:web/H5 WS 优先+轮询兜底;H5 聊天室/任务页与 web /tasks 管理页均已接 task:changed/chat:* 实时事件。

### 节假日告警静默(NAS;2026-11-07 落地)
```bash
ssh yyc3-45
cd /Volume3/docker/yyc3-0379-world/deploy/nas
bash am-holiday-silence.sh --list      # 查看有效静默
bash am-holiday-silence.sh --dry-run   # 预览
bash am-holiday-silence.sh --apply     # 创建/刷新(幂等,标记 holiday:<名>-<年>)
bash am-holiday-silence.sh --remove    # 清理
```
- 日期表 `holidays.json` 每年 12 月按国务院公告核定更新后重跑 `--apply`。
- **⚠️ AM 重启后静默全失(2026-11-07 实测)**:当前部署 silences 存储文件 0 字节=不跨重启持久;**每次 AM 重启/reseed 后必须重跑 `am-holiday-silence.sh --apply`(恒 7 条 pending 为健康态)**。
- 默认静默 RoomsHigh/Saturated(warning|info);LeisureApiDown(critical)永不静默。
- 坑:AM silence DELETE=标记过期(expired 行留在 GET 列表,--list 已过滤);busybox wget 无 `--method=DELETE` → 脚本走宿主 python3 urllib 直连容器网桥 IP。

## 四、数据库变更（迁移纪律）

- 只加列/加表，不破坏（红线）；迁移文件入 git
- 流程：`migrate deploy`（owner 账号）→ `apply-pg-grants.sql` → 重启 API 实例（Prisma client 结构变更时）
- 已应用迁移台账：
  - `20261102040000_pg_baseline`：PG15 基线（38 表）
  - `20261103000000_ticket_settle_and_booking_hold`（**P1 批次，2026-11-03**）：`room_session.ticket_deduct_amount` + `artist_booking.deposit/hold_minutes/hold_until/call_id`——纯加列,旧代码兼容,可直接回退
- seed：`NODE_ENV=prod` 自动跳过 admin/china/e2epwd 测试账号；seed 含 3 个示例销售经理（未审核，可在档案页软删）

## 五、前端发布注意

- Web 为同源相对路径（`/api/v1`），无内嵌地址
- H5 的 `API_BASE` 为**编译期内联**：`TARO_APP_API_BASE='https://lm.0379.pro/api/v1' pnpm build:h5`——改域名必须重构建
- 小程序（weapp）发布走同一 `API_BASE` 机制 + 微信后台合法域名配置

## 六、回退

- **后端**：`launchctl` 卸载新进程 → `git checkout <旧tag>` → `pnpm build` → KeepAlive 拉起（迁移只加列，旧镜像/旧代码兼容）
- **前端**：ECS 保留上一版目录或 `git` 重建旧 dist 覆盖
- **DB**：主备流复制天然热备；灾难恢复用 `pg_dump` 每日份（NAS V1 池）
