## 一、现状权限链路(已实现,全链路盘点)

| 层 | 机制 | 实现位置 |
|---|---|---|
| 认证 | 管理端手机号+密码 → JWT(access 2h/refresh 7d);连错 5 次锁 15 分钟;首登必改密(40302) | services/leisure-api `auth` 模块 |
| 授权(接口) | `@RequirePerm('功能码')` 守卫,逐接口声明;JWT payload 携带 permCodes[] | `common/guards/jwt.guard.ts` |
| 授权(前端) | 路由/菜单/工作台宫格统一按 permCodes 过滤(单源 Sidebar MENU) | `Sidebar.tsx`/`RequirePerm` |
| 端别 scope | JWT `scope: ADMIN / ARTIST`;ARTIST 端点强制本人(`/tickets/my`、`/me/orders` 等) | 各模块控制器 |
| 数据范围 | 主管角色查询强制本组(group_id);多店用户-store 映射 | 查询层(主管报表等) |
| DB 红线 | leisure_app 对流水/审计/台票三表仅 SELECT+INSERT;更正只走 REVERSE | `apply-pg-grants.sql` |
| 审计 | 全动作 audit_log(谁/何时/何地/何事/前后值),DB 层禁删 | `audit` 红线 |

**缺口(= 本模块要补的)**:账号/角色仅能 seed+SQL 维护;无部门/组织实体;无权限管理 UI;数据范围仅"组"一级。

## 二、目标组织架构(术语裁决落地)

```
门店(store)
└─ 销售副总(管理职,每店 1 名;全店数据范围)
   ├─ 销售总监(管理职;分管若干部门/组,数据范围=所辖部门)
   │   └─ 销售经理(一线,数据范围=本人)
   └─ 职能岗位(收银员/财务——不属销售线,按功能码授权)
```

- **组织实体**:`department`(部门,树形,parent_id;种子部门建议:销售一部/销售二部/…或按总监命名)
- **职级**:`admin_user.title`(MANAGER_DIRECTOR=销售总监 / MANAGER=销售经理 / VP=销售副总 / CASHIER / FINANCE)——职级与角色解耦(角色=功能码集合,职级=数据范围与汇报线)
- **汇报线**:`admin_user.manager_id`(销售经理→其销售总监;销售总监→销售副总)——为提成/业绩归属预留(III-B)

## 三、员工管理三板块设计(确认后实施)

### 3.1 员工信息(管理端 /staff 页)

- 列表:姓名/手机号/部门/角色/职级/状态/最近登录;筛选(部门/角色/状态);停用=软删(保留审计)
- 新建/编辑:姓名*、手机号*、部门、角色(多选或单选,见 4.2)、职级、直属上级(销售线必填)
- 重置密码:管理员重置 → 临时密码+`must_change_password=true`(复用首登改密链路 40302)
- 数据链路:新建后首登同样强制改密;全部动作入审计

### 3.2 部门管理(/staff/departments)

- 树形展示(公司 → 部门 → 小组两级足够);部门 CRUD(同名店内唯一)
- 部门主管(指向员工);部门成员数
- 数据范围挂钩:销售总监角色 × 所辖部门 → 查询注入 `department_id IN (...)`(替代现"组"维度;artist.group_id 迁移为部门映射,过渡期双写)

### 3.3 权限管理(/staff/roles)

- 角色 CRUD(预置角色不可删:管理员/销售总监/财务/收银员)
- 功能码矩阵:行=角色,列=功能码域(档案/配置/台费/台票/考勤/场次/展示/订单评价/系统),勾选保存 → permCodes JSON
- 员工-角色分配在 3.1 编辑内完成;角色变更即时生效(下次请求 JWT 仍带旧码 → 实现方式:权限变更后吊销该用户 refresh,强制重登)

### 3.4 API/schema 草案

```
model Department { id, storeId, name, parentId?, headUserId?, createdAt, deletedAt }
model AdminUser   { +departmentId?, +title?, +managerId? }        // 三列迁移,纯加列
POST   /staff/users            (setting:manage)                   // 建号(重置密码复用)
GET    /staff/users            ?departmentId&status&keyword
PUT    /staff/users/:id        / POST /staff/users/:id/reset-password
POST   /staff/users/:id/disable
GET/POST/PUT/DELETE /staff/departments(/:id)
GET/POST/PUT/DELETE /staff/roles(/:id)   (permCodes 数组体)
```

前端:`/staff`(员工信息)、`/staff/departments`、`/staff/roles` 三页 + 移动工作台「更多」分组挂入(按 setting:manage 过滤)。

## 五、待 Owner 确认的决策点

| # | 决策点 | 选项 |
|---|---|---|
| 1 | 部门层级深度 | 两级(部门/小组)推荐 vs 任意树 |
| 2 | 角色模型 | 单角色/人(推荐,简单清晰) vs 多角色/人(功能码并集) |
| 3 | 销售总监数据范围 | 所辖部门(推荐) vs 全店只读 |
| 4 | 销售副总账号 | 是否同时保留全店管理权限(推荐=是,复用管理员之外的第二管理职) |
| 5 | 原"组别"(artist.group_id)与新部门关系 | 迁移映射(推荐,过渡双写) vs 并存两套 |
| 6 | 权限变更生效方式 | 吊销 refresh 强制重登(推荐,即时安全) vs JWT 短时效自然过期(体验好但最长 2h 旧权限) |
