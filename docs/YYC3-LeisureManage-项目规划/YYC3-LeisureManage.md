## 第一章 系统概述

### 1.1 系统定位

本系统为 KTV / 商务会所 / 夜总会类门店的**艺人（技师）管理后台**，覆盖艺人档案、考勤报备、上钟调度、台费账户、台票体系、订单预约、服务评价与财务对账全流程，支持多门店独立运营。

### 1.2 目标用户与角色

| 角色 | 主要职责 | 使用模块范围 |
| --- | --- | --- |
| 超级管理员 | 系统参数配置、全局数据维护 | 全部模块 |
| 门店店长/主管 | 艺人分组定级、台费定价、报备审批、调度监管 | 档案域、考勤域、资金域、报表域 |
| 前台/钟房 | 上钟派单、下钟结算、台票核销、手动扣费 | 上下钟、台费、台票模块 |
| 财务 | 充值/扣费对账、报表导出 | 资金域、报表域 |
| 艺人（移动端） | 扫码登录、报备签到、自助绑定资料、扫码上下钟 | 自助绑定、报备、上下钟 |

### 1.3 业务场景概述

1. 门店先维护**基础主数据**（艺人档案、组别、等级、包厢房号、台费价格、台票票种）；
2. 艺人每日**报备签到**，进入**实时在岗调度池**；
3. 客人开包厢后，前台为艺人**派单上钟**（选择包厢房号，按小时计费）；
4. 下钟时系统按**计费规则**自动核算金额，从艺人**台费账户**扣减；
5. 台票购买与核销形成独立台账，订单完成后客户**评价**；
6. 财务通过**明细/汇总报表**完成对账。

## 第二章 系统总体架构

### 2.1 三层业务架构

| 层级 | 名称 | 内容 | 模块示例 |
| --- | --- | --- | --- |
| 第一层 | 基础配置层（主数据） | 艺人档案、组别、等级、台费价格、包厢房号、台票设置、系统参数 | 艺人资料管理、艺人等级、包厢房号管理、台费设置、艺人设置 |
| 第二层 | 现场运营层（日常业务） | 考勤报备、上钟调度、订单预约、台票核销 | 艺人实时状态、艺人上下钟、艺人报备、艺人订单 |
| 第三层 | 资金与报表层（财务对账） | 台费账户充值扣费、流水记录、客户评价、数据汇总导出 | 台费充值/扣费记录、服务评价、艺人报表 |

| 102 | 展示 & 对外曝光域 | C端艺人展示入口与展示控制 |

### 2.3 整体业务闭环

```
系统参数配置（艺人设置：上钟模式/计费规则/报备规则）
        ↓
包厢房号档案维护 → 艺人档案/组别/等级 → 台费与台票价格配置
        ↓
艺人每日报备签到（受报备规则开关控制）
        ↓
现场调度 → 派单上钟（选择包厢房号，小时计费，包厢置为占用）
        ↓
下钟结算（按“超时15分钟计1小时”核算 → 自动扣台费 / 核销台票）
        ↓
台费充值/扣费账户流水 → 订单归档 + 客户评价
        ↓
明细/汇总报表导出对账（含包厢房号维度）
```

## 第四章 各模块页面详细需求

### 模块1：艺人实时状态（已核验）

**页面定位**：现场调度看板，实时监控艺人在岗状态，供管理人员派单调度。

| 项 | 内容 |
| --- | --- |
| 筛选条件 | 门店下拉、组别下拉、艺名/腰牌号切换搜索（底部弹窗选择字段） |
| 顶部统计 | 总人数、签到、上钟、串台、空闲、被选中 |
| 核心操作 | 查看在岗状态、按状态调度 |
| 业务规则 | 上钟后状态自动变为「上钟」，下钟恢复「空闲」；串台为第二台并行状态 |

### 模块2：艺人展示（已核验）

**页面定位**：C端/客端展示入口，客户扫码进入艺人形象展示页挑选艺人。

| 项 | 内容 |
| --- | --- |
| 核心操作 | 点击【去扫码】生成登录二维码 |
| 业务规则 | 仅审核通过的艺人对外展示 |

### 模块3：艺人资料管理（已核验，含多子页面）

**3.1 列表主页**

- 筛选：门店、组别、审核状态（全部 / 等待审核 / 审核未通过 / 审核通过）、姓名搜索
- 顶部按钮：添加艺人；底部按钮：批量设置
- 业务规则：资料审核通过后才对外展示

**3.2 添加艺人资料（新增表单）**

| 分组 | 字段 |
| --- | --- |
| 归属与权限 | 门店、组别（必填）、主管、业绩指标、等级、标签、腰牌号、ID卡号 |
| 上钟规则 | 总上台次数、允许串台数、首台最低上钟时长、同包厢上钟最低时长、上下班时间 |
| 计费配置 | 小费设置（一口价）、计时单价 |
| 身份信息 | 姓名、艺名（必填）、性别、手机号（必填）、身份证号 |
| 形象资料 | 照片、身份证正反面、身高/体重/三围（胸/腰/臀）、简介（最多200字） |
| 展示素材 | 个人写真（最多9张）、近身照（1张）、全身照（最多6张）、展示视频（1条≤15s） |

**3.3 艺人资料批量设置**

- 筛选：门店、等级
- 可批量勾选修改：总上台次数、允许串台数、首台最低时长、同包厢上钟时长、上下班时间、一口价小费、计时单价

**3.4 审核状态枚举**：全部 / 等待审核 / 审核未通过 / 审核通过

### 模块4：艺人上下钟（已核验，已按会话二更新）

**页面定位**：查询技师上钟、串台流水，统计出勤服务。

- 筛选：门店、区域、包厢类型、时间区间、艺名/腰牌、组别；标签（全部 / 上钟 / 串台）
- 核心操作：查看记录、打印导出
- **会话二更新**：
  - 上钟必须选择包厢房号，自动带出包厢类型并匹配计时单价；
  - 下钟自动按「进位阈值（门店可配，默认15分钟）」核算计费时长与金额；
  - 记录增加字段：包厢房号、包厢类型、开始/结束时间、计费小时、单价、金额；
  - 上钟中包厢自动标记「占用」，下钟恢复「空闲」。

### 模块5：艺人注册二维码（待补充页面细节）

**功能定位**：生成艺人注册二维码，艺人扫码进入自助绑定/注册流程，提交资料待审核。
**建议字段**：门店、二维码有效期、注册来源统计。

### 模块6：艺人台费设置（已核验）

**页面定位**：配置不同等级艺人在不同包厢类型的台费/计时单价标准。

- 筛选：门店、艺人等级、包厢类型
- 操作：新增（右上角+）、修改、删除
- 字段：艺人等级、包厢类型、计时单价（元/小时）、一口价小费、生效状态
- **会话二联动**：包厢类型来自【包厢房号管理】；上钟选择包厢后自动带出单价

### 模块7：艺人组别（已核验）

**页面定位**：分组管理艺人，绑定主管，用于业绩归属与报备汇总。

- 筛选：门店
- 操作：新增组别、修改、删除、员工增减（给组别增删艺人）
- 字段：组别名称、主管、所属门店、艺人数量、备注

### 模块8：艺人报备明细（已核验）

**页面定位**：艺人当日/指定日期报备状态明细（签到/例假/陪宴/私事）。

- 筛选：门店、组别、报备状态、日期、艺名
- 操作：查看明细、打印
- 状态枚举：签到、陪宴、私事、早退、迟到、例假、其他、未报备（8 种，与报备汇总/领域单源对齐）

### 模块9：艺人报备汇总（已核验）

## 第六章 计费规则（小时计费 + 可配置进位阈值）

### 6.1 规则定义

- 基础计费单位：**1小时**；
- 计费模式：**小时计费**；
- 进位阈值：**剩余分钟 > N 时向上进位1小时**；**N 为门店级自定义参数**（分钟，默认 15，管理端可编辑）。

### 6.2 计费对照表

| 实际时长（分钟） | 计费小时数 | 说明 |
| --- | --- | --- |
| ≤ 60 | 1 | 首小时 |
| 61 – 75 | 2 | 超时16–15分钟 → 进位 |
| 76 – 120 | 2 | 满2小时 |
| 121 – 135 | 3 | 超时16–15分钟 → 进位 |
| 136 – 180 | 3 | 满3小时 |
| 181 – 195 | 4 | 依此类推 |

> 进位边界（按默认阈值 N=15 示例）：**剩余分钟 ≤ N 不进位，> N 进位**。例：75分钟→剩余15分钟→不计进位→2小时；76分钟→剩余16分钟→进位→2小时（即76分钟仍为2小时，与上表一致）。阈值 N 由门店自定义后，对照表按 N 重算。

### 6.3 计费算法（后端伪代码）

```
function calcBillHours(actualMinutes, N = 15):        # N = 门店进位阈值(分钟,可自定义编辑)
    baseHours = floor(actualMinutes / 60)
    remain    = actualMinutes % 60
    if remain > N:
        return baseHours + 1
    else:
        return baseHours

function calcBillAmount(actualMinutes, unitPrice):
    hours = calcBillHours(actualMinutes)
    return hours * unitPrice
```

### 6.4 配置项（放入艺人设置）

| 配置项 | 取值 | 说明 |
| --- | --- | --- |
| 计费模式 | 小时计费（当前启用） | 预留：一口价模式 |
| 进位阈值 | 自定义分钟数（默认 15） | **门店可编辑**：剩余分钟 > 阈值即进位1小时；改后即时生效（进行中场次仍按上钟时快照阈值计） |
| 是否启用进位规则 | 开启/关闭 | 关闭则按实际时长精确到小时（向下取整或四舍五入另行配置） |
| 跨天处理 | 连续累计 | 班次周期 08:00~次日08:00，跨天上钟时长不截断 |

### 6.5 艺人上下钟计费流程（方案甲 2026-11-01 裁决：时间费计入房账，关房统一结算）

1. 艺人上钟：必须选择包厢房号 → 系统读取包厢类型 → 按**房计时单价快照**计费（方案甲：不再按「等级×房型」匹配，台费设置转为 II 期客人消费模式预留）；
2. 上钟记录：开始时间、包厢房号、包厢类型、艺人、单价，包厢置为「占用」；
3. 下钟：记录结束时间 → 计算实际时长 → 按进位规则计算计费小时；
4. 金额核算：`计费小时 × 计时单价` → **计入房账（不即扣台费、不落流水）**；
5. **关房统一结算**：结算单 = Σ上钟时间费 + Σ艺人自点单；支付方式 = 现金 / 台费余额抵扣 / 混合；台费抵扣部分生成 `ROOM_SETTLE` 流水（替代原「艺人台费扣费记录」中的上钟消费类目）；
6. 结算明细写入「艺人上下钟明细报表」（带包厢房号字段）。

### 6.6 边界异常规则

| 场景 | 处理规则 |
| --- | --- |
| 中途切换包厢 | 支持转包厢：终止当前计时，新开一条上钟记录 |
| 手动/后台强制下钟 | 同样按15分钟进位规则计算 |
| 串台 | 串台同样绑定包厢，分别计时、独立核算 |
| 台票抵扣 | 小时计费订单仍支持台票抵扣，抵扣后再扣台费余额 |
| 一口价与计时并存 | 可配置本次走一口价或小时计时 |
