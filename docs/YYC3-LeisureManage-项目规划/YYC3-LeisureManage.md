## 第一章 系统概述

### 1.1 系统定位

本系统为 KTV / 商务会所 / 夜总会类门店的**艺人（技师）管理后台**，覆盖艺人档案、考勤报备、上钟调度、台费账户、台票体系、订单预约、服务评价与财务对账全流程，支持多门店独立运营。

### 1.2 目标用户与角色

| 角色 | 主要职责 | 使用模块范围 |
| --- | --- | --- |
| 超级管理员 | 系统参数配置、全局数据维护 | 全部模块 |
| 门店店长/主管 | 艺人分组定级、台费定价、报备审批、调度监管 | 档案域、考勤域、资金域、报表域 |
| 前台/钟房 | 上钟派单、下钟结算、台票核销、手动扣费 | 上下钟、台费、台票模块 |
| 财务 | 充值/扣费对账、报表导出 | 资金域、报表域 |
| 艺人（移动端） | 扫码登录、报备签到、自助绑定资料、扫码上下钟 | 自助绑定、报备、上下钟 |

### 1.3 业务场景概述

1. 门店先维护**基础主数据**（艺人档案、组别、等级、包厢房号、台费价格、台票票种）；
2. 艺人每日**报备签到**，进入**实时在岗调度池**；
3. 客人开包厢后，前台为艺人**派单上钟**（选择包厢房号，按小时计费）；
4. 下钟时系统按**计费规则**自动核算金额，从艺人**台费账户**扣减；
5. 台票购买与核销形成独立台账，订单完成后客户**评价**；
6. 财务通过**明细/汇总报表**完成对账。

## 第二章 系统总体架构

### 2.1 三层业务架构

| 层级 | 名称 | 内容 | 模块示例 |
| --- | --- | --- | --- |
| 第一层 | 基础配置层（主数据） | 艺人档案、组别、等级、台费价格、包厢房号、台票设置、系统参数 | 艺人资料管理、艺人等级、包厢房号管理、台费设置、艺人设置 |
| 第二层 | 现场运营层（日常业务） | 考勤报备、上钟调度、订单预约、台票核销 | 艺人实时状态、艺人上下钟、艺人报备、艺人订单 |
| 第三层 | 资金与报表层（财务对账） | 台费账户充值扣费、流水记录、客户评价、数据汇总导出 | 台费充值/扣费记录、服务评价、艺人报表 |

### 2.2 八大业务域（菜单权限分组）

| 域编号 | 业务域 | 说明 |
| --- | --- | --- |
| 101 | 艺人档案 & 基础信息域 | 档案、自助绑定、组别、等级、注册二维码 |
| 102 | 展示 & 对外曝光域 | C端艺人展示入口与展示控制 |
| 103 | 考勤、上钟、报备域 | 实时状态、上下钟、补打卡、报备、包厢房号 |

| 108 | 艺人报表域 | 财务/运营/主管考核报表 |

### 2.3 整体业务闭环

```
系统参数配置（艺人设置：上钟模式/计费规则/报备规则）
        ↓
包厢房号档案维护 → 艺人档案/组别/等级 → 台费与台票价格配置
        ↓
艺人每日报备签到（受报备规则开关控制）
        ↓
现场调度 → 派单上钟（选择包厢房号，小时计费，包厢置为占用）
        ↓
下钟结算（按“超时15分钟计1小时”核算 → 自动扣台费 / 核销台票）
        ↓
台费充值/扣费账户流水 → 订单归档 + 客户评价
        ↓
明细/汇总报表导出对账（含包厢房号维度）
```

## 第四章 各模块页面详细需求

### 模块1：艺人实时状态（已核验）

**页面定位**：现场调度看板，实时监控艺人在岗状态，供管理人员派单调度。

| 项 | 内容 |
| --- | --- |
| 筛选条件 | 门店下拉、组别下拉、艺名/腰牌号切换搜索（底部弹窗选择字段） |
| 顶部统计 | 总人数、签到、上钟、串台、空闲、被选中 |
| 核心操作 | 查看在岗状态、按状态调度 |
| 业务规则 | 上钟后状态自动变为「上钟」，下钟恢复「空闲」；串台为第二台并行状态 |

### 模块2：艺人展示（已核验）

**页面定位**：C端/客端展示入口，客户扫码进入艺人形象展示页挑选艺人。

| 项 | 内容 |
| --- | --- |
| 核心操作 | 点击【去扫码】生成登录二维码 |
| 业务规则 | 仅审核通过的艺人对外展示 |

### 模块3：艺人资料管理（已核验，含多子页面）

**3.1 列表主页**

- 筛选：门店、组别、审核状态（全部 / 等待审核 / 审核未通过 / 审核通过）、姓名搜索
- 顶部按钮：添加艺人；底部按钮：批量设置
- 业务规则：资料审核通过后才对外展示

**3.2 添加艺人资料（新增表单）**

| 分组 | 字段 |
| --- | --- |
| 归属与权限 | 门店、组别（必填）、主管、业绩指标、等级、标签、腰牌号、ID卡号 |
| 上钟规则 | 总上台次数、允许串台数、首台最低上钟时长、同包厢上钟最低时长、上下班时间 |
| 计费配置 | 小费设置（一口价）、计时单价 |
| 身份信息 | 姓名、艺名（必填）、性别、手机号（必填）、身份证号 |
| 形象资料 | 照片、身份证正反面、身高/体重/三围（胸/腰/臀）、简介（最多200字） |
| 展示素材 | 个人写真（最多9张）、近身照（1张）、全身照（最多6张）、展示视频（1条≤15s） |

**3.3 艺人资料批量设置**

- 筛选：门店、等级
- 可批量勾选修改：总上台次数、允许串台数、首台最低时长、同包厢上钟时长、上下班时间、一口价小费、计时单价

**3.4 审核状态枚举**：全部 / 等待审核 / 审核未通过 / 审核通过

### 模块4：艺人上下钟（已核验，已按会话二更新）

**页面定位**：查询技师上钟、串台流水，统计出勤服务。

- 筛选：门店、区域、包厢类型、时间区间、艺名/腰牌、组别；标签（全部 / 上钟 / 串台）
- 核心操作：查看记录、打印导出
- **会话二更新**：
  - 上钟必须选择包厢房号，自动带出包厢类型并匹配计时单价；
  - 下钟自动按「超时15分钟进位」核算计费时长与金额；
  - 记录增加字段：包厢房号、包厢类型、开始/结束时间、计费小时、单价、金额；
  - 上钟中包厢自动标记「占用」，下钟恢复「空闲」。

### 模块5：艺人注册二维码（待补充页面细节）

**功能定位**：生成艺人注册二维码，艺人扫码进入自助绑定/注册流程，提交资料待审核。
**建议字段**：门店、二维码有效期、注册来源统计。

### 模块6：艺人台费设置（已核验）

**页面定位**：配置不同等级艺人在不同包厢类型的台费/计时单价标准。

- 筛选：门店、艺人等级、包厢类型
- 操作：新增（右上角+）、修改、删除
- 字段：艺人等级、包厢类型、计时单价（元/小时）、一口价小费、生效状态
- **会话二联动**：包厢类型来自【包厢房号管理】；上钟选择包厢后自动带出单价

### 模块7：艺人组别（已核验）

**页面定位**：分组管理艺人，绑定主管，用于业绩归属与报备汇总。

- 筛选：门店
- 操作：新增组别、修改、删除、员工增减（给组别增删艺人）
- 字段：组别名称、主管、所属门店、艺人数量、备注

### 模块8：艺人报备明细（已核验）

**页面定位**：艺人当日/指定日期报备状态明细（签到/例假/陪宴/私事）。

- 筛选：门店、组别、报备状态、日期、艺名
- 操作：查看明细、打印
- 状态枚举：签到、例假、陪宴、私事

### 模块9：艺人报备汇总（已核验）

**页面定位**：按组别/主管汇总当日技师报备大盘。

- 筛选：门店、组别、主管、日期
- 操作：汇总统计、打印
- 统计口径：各组出勤人数、请假人数、报备状态分布

### 模块10：艺人台费充值记录（已核验）

**页面定位**：技师台费账户充值流水台账。

- 筛选：门店、组别、时间区间、腰牌号/艺名
- 操作：查看充值记录、打印

## 第六章 计费规则（小时计费 + 超时15分钟进位）

### 6.1 规则定义

- 基础计费单位：**1小时**；
- 计费模式：**小时计费**；
- 进位阈值：**剩余分钟 > N 时向上进位1小时**；**N 为门店级自定义参数**（分钟，默认 15，管理端可编辑）。

### 6.2 计费对照表

| 实际时长（分钟） | 计费小时数 | 说明 |
| --- | --- | --- |
| ≤ 60 | 1 | 首小时 |
| 61 – 75 | 2 | 超时16–15分钟 → 进位 |
| 76 – 120 | 2 | 满2小时 |
| 121 – 135 | 3 | 超时16–15分钟 → 进位 |
| 136 – 180 | 3 | 满3小时 |
| 181 – 195 | 4 | 依此类推 |

> 进位边界（按默认阈值 N=15 示例）：**剩余分钟 ≤ N 不进位，> N 进位**。例：75分钟→剩余15分钟→不计进位→2小时；76分钟→剩余16分钟→进位→2小时（即76分钟仍为2小时，与上表一致）。阈值 N 由门店自定义后，对照表按 N 重算。

### 6.3 计费算法（后端伪代码）

```
function calcBillHours(actualMinutes, N = 15):        # N = 门店进位阈值(分钟,可自定义编辑)
    baseHours = floor(actualMinutes / 60)
    remain    = actualMinutes % 60
    if remain > N:
        return baseHours + 1
    else:
        return baseHours

function calcBillAmount(actualMinutes, unitPrice):
    hours = calcBillHours(actualMinutes)
    return hours * unitPrice
```

### 6.4 配置项（放入艺人设置）

| 配置项 | 取值 | 说明 |
| --- | --- | --- |
| 计费模式 | 小时计费（当前启用） | 预留：一口价模式 |
| 进位阈值 | 自定义分钟数（默认 15） | **门店可编辑**：剩余分钟 > 阈值即进位1小时；改后即时生效（进行中场次仍按上钟时快照阈值计） |
| 是否启用进位规则 | 开启/关闭 | 关闭则按实际时长精确到小时（向下取整或四舍五入另行配置） |
| 跨天处理 | 连续累计 | 班次周期 08:00~次日08:00，跨天上钟时长不截断 |

### 6.5 艺人上下钟计费流程（更新后）

1. 艺人上钟：必须选择包厢房号 → 系统读取包厢类型 → 匹配艺人等级对应计时单价；
2. 上钟记录：开始时间、包厢房号、包厢类型、艺人、单价，包厢置为「占用」；
3. 下钟：记录结束时间 → 计算实际时长 → 按进位规则计算计费小时；
4. 金额核算：`计费小时 × 计时单价`；
5. 自动扣减台费账户，生成一条「艺人台费扣费记录」；
6. 流水写入「艺人上下钟明细报表」（带包厢房号字段）。

### 6.6 边界异常规则

| 场景 | 处理规则 |
| --- | --- |
| 中途切换包厢 | 支持转包厢：终止当前计时，新开一条上钟记录 |
| 手动/后台强制下钟 | 同样按15分钟进位规则计算 |
| 串台 | 串台同样绑定包厢，分别计时、独立核算 |
| 台票抵扣 | 小时计费订单仍支持台票抵扣，抵扣后再扣台费余额 |
| 一口价与计时并存 | 可配置本次走一口价或小时计时 |

## 第十二章 同赛道开源项目对标评估与缺失项补齐（会话三新增）

### 12.1 对标结论（核心）
>
> 开源社区**没有完全匹配「会所艺人轮台 + 台费账户 + 包厢计时」的开源成品**；主流开源项目仅覆盖【包厢计时收银】或【OA排班考勤】单一模块。会所特有业务（台费钱包、轮台公平调度、转销售分成、打赏合单）必须自研，但底层组件、计费引擎、权限框架可直接复用。

### 12.2 同类开源项目清单与对标

| 开源项目 | 技术栈 | 擅长模块 | 与本系统对标短板 |
| --- | --- | --- | --- |
| TimerPOS | Vue3 + FastAPI + Electron | 包厢房态、小时计时、阶梯取整、商品收银、本地离线计时 | 无艺人轮台、台费账户、业绩分成、转销售、打赏审批 |
| RoomCtr | C#/Web + SQLite | 包间状态、暂停续时、灵活取整计费、硬件联动（灯控） | 无艺人排班、轮台、业绩核算 |
| FastAdmin 排班插件 | ThinkPHP + Bootstrap | 组织架构、员工考勤、审批、换班请假、班次 | 无包厢计时、上钟下钟、轮台调度、台费钱包 |
| Odoo Entertainment / Nx Gaming | Python Odoo | 可配置计费引擎（进位规则、时段浮动价、最低消费、封顶计费） | 欧美模型，缺国内轮台/转销售/合单/打赏/台票本土业务，权限体系重 |
| Dolibarr SalonManager | PHP | 美容技师预约、提成核算、工单 | 预约制，不支持现场轮台、包厢实时房态 |
| timecard-engine（NPM） | JS | 独立计时取整SDK（任意分钟进位） | 纯算法包，无业务页面 |

> 社区高频路线：**FastAdmin + 自研计时引擎**二次开发，是国内会所系统低成本落地的主流方案。

### 12.3 现有能力盘点（对照移动端菜单 + Web后台）

- 已覆盖：包厢房态与小时计费（15分钟进位）、签到报备、上下钟、台费账户、台票体系、审批流、组织权限、业绩统计（分成/订房/转销售/打赏/合单）、商品后厨柜子增值业务、客资列表、系统防护。

### 12.4 缺失功能清单（行业对标，分级）

#### 🔴 P0 核心缺失（行业刚需，优先补齐）

1. **可视化钟房大屏（轮台调度看板）**：大屏展示包厢状态、排队艺人队列、空闲/上钟/待叫钟、语音叫钟播报；当前仅有后台报表，缺现场调度核心载体；
2. **计时会话状态机**：暂停 / 续钟 / 换房 / 转钟 / 加钟；跨包厢转钟**分段计费**（按不同包厢单价分别结算）；当前仅有「上钟-下钟」两态；
3. **时段差异化定价引擎**：早场/晚场、节假日、周末自动切换单价；当前仅固定包厢单价，缺浮动价、最低消费、封顶计费；
4. **离线计时兜底**：本地缓存计时，断网不丢钟、恢复自动同步（TimerPOS成熟方案）；
5. **硬件联动接口层**：包厢灯控、门禁、IP音响、柜子锁联动；开钟自动开灯、下钟延时断电（与现有柜子管理打通）。

#### 🟠 P1 业务闭环缺失

1. **客户客资CRM完整链路**：客户标签、消费档案、历史包厢、偏好艺人、跟进记录、回访提醒、储值卡、优惠券；
2. **预约锁钟与超时释放**：预约锁艺人+锁包厢、超时自动释放、预约押金、变更审批；
3. **交接班对账模块**：当班收银/业绩/未结订单、交接班签字、交接日志；
4. **提成规则引擎（柔性配置）**：可视化配置项目提成比例、阶梯提成、主管抽成、团队分成、打赏提成独立开关；
5. **消息推送矩阵**：技师端叫钟/下钟/业绩到账推送；主管端异常告警；客户端预约提醒（企微/短信/推送）。

#### 🟡 P2 体验与扩展缺失

1. **PWA技师端（离线H5）**：免安装扫码直接上钟下钟；
2. **预警告警体系**：包厢超时预警、艺人超时长在岗、未下钟过夜、账户余额不足（Redis延时队列）；
3. **库存+后厨联动闭环**：包厢点单自动关联当前上钟订单、商品消费计入包厢账单、库存扣减、后厨打印分单；
4. **数据看板BI大屏**：包厢使用率、到店率、营收曲线、轮台公平性热力图（可嵌入Apache Superset）；
5. **风控审计日志**：异常订单、免单、手动扣费全部留痕（对应系统防护）。

### 12.5 开源可借鉴核心技术

| 技术点 | 开源方案 | 落地方式 |
| --- | --- | --- |
| 计时取整引擎 | timecard-engine（NPM） | 独立封装成后端微服务，支持15分钟进位、分段计时、跨天累计 |
| 上钟状态机 | XState | 管理空闲→上钟→暂停→续钟→转钟→下钟生命周期，避免if-else堆积 |
| 后台框架 | FastAdmin（ThinkPHP+Vue） | 国内二次开发首选：权限、组织架构、审批、报表、导入导出原生自带 |
| 实时推送 | Redis + WebSocket/SSE | 包厢房态、在岗状态、排钟队列内存缓存 + 实时刷新钟房大屏 |
| 报表导出 | EasyExcel(Java) / openpyxl(Python) | 后端导出；前端ECharts/v-charts业绩图表；Superset嵌入BI |
| 审批流引擎 | Flowable / JeecgBoot工作流 | 报备审批、换班审批、免单审批、异常订单审批 |
| 离线能力 | PWA + IndexedDB | 本地缓存计时记录，网络恢复幂等同步 |

### 12.6 风险提示

1. 无开源项目原生支持「艺人台费钱包 + 轮台公平调度 + 转销售分成 + 打赏合单」本土会所业务，**业务层必须自研**；
2. Odoo、Dolibarr为海外ERP，提成/订单模型与国内会所逻辑差异大，改造量极高；
3. FastAdmin适合做底座，但商店插件多为通用OA，轮台、计时模块需自行开发。

### 12.7 落地建议路线

1. **底座**：选用 FastAdmin（组织架构、身份权限、审批、报表直接复用）；
2. **独立封装**：计时取整微服务（基于timecard-engine改造，支持15分钟进位、分段、转包厢）；
3. **自研核心业务**：艺人轮台调度、台费账户、台票、合单打赏、转销售分成（差异化核心，无开源替代）；
4. **扩展层**：WebSocket钟房大屏、PWA技师端、硬件联动。
