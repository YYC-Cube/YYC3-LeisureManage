## 三、四端技术栈方案(LeisureManage)

### 3.0 总览

```
                    ┌────────────────────────────┐
                    │  后端 API(NestJS/Spring)    │
                    │  MySQL · Redis · OSS        │
                    └─────────────┬──────────────┘
          ┌───────────────┬───────┴────────┬──────────────┐
   ┌──────▼──────┐ ┌──────▼──────┐ ┌───────▼─────┐ ┌──────▼──────┐
   │ Web 管理端   │ │ PWA 移动端   │ │ 微信小程序    │ │ 桌面(可选)  │
   │ 店长/管理员  │ │ 收银/主管     │ │ 销售端       │ │ 收银大屏     │
   ├─────────────┼──────────────┼───────────────┼──────────────┤
   │ React19     │ 同一 Web 工程 │ Taro4(React)  │ Electron41   │
   │ Vite8       │ 响应式+BottomNav│ NutUI-React× │ (复用 web-full│
   │ @yyc3/ui    │ +PWA 基建     │ @yyc3/theme   │  壳模式)     │
   │ @yyc3/shell │ (现成)        │ (令牌映射)     │              │
   │ Sidebar 布局 │               │ @yyc3/core 逻辑│              │
   └─────────────┘ └─────────────┘ └──────────────┘ └─────────────┘
   共享:@yyc3/core(领域逻辑/类型/API client) · @yyc3/theme(令牌) · OpenAPI
```

### 3.1 Web 管理端(店长/管理员/财务)——**直接挂入 DeepStack**
- 新建 `apps/app-leisure-web`,复制 app-web-full 工程骨架(Vite8+React19+router7+zustand5+Tailwind4)
- UI:**@yyc3/ui** 49 件按 05 文档页面映射(table/tabs/form/dialog/select/command/chart)
- 壳层:**@yyc3/shell** Sidebar + RequireRole + CommandPalette(全局搜腰牌号/艺名)
- 报表:ui/chart + 导出;报备汇总矩阵用 table 粘性表头
- 工时修正:壳层与通用件复用,**管理后台预估 16→10 人日**

### 3.2 PWA 移动端(收银/主管随身)——**同一 Web 工程的移动形态**
- 不新建工程:app-leisure-web 响应式断点(<768px)切换 **@yyc3/shell BottomNav** 布局
- 启用 app-web-full 现成 PWA 件:manifest + usePWAManager + InstallPrompt(迁移三文件即可)
- 场景页面:扫码签到现场屏(全屏二维码)/实时看板/快速上钟下钟/补打卡——移动优先设计
- 收益:iOS/Android 免上架;离线签到队列(core/yyc3-storage)

### 3.3 销售端微信小程序——**Taro 4 + React(新建)**
- 选型对比:
  | 方案 | 与 DeepStack 契合 | 结论 |
  |---|---|---|
  | **Taro 4(React)** | JSX 语法同源;@yyc3/core(纯 TS 逻辑)可直接 import;theme 的 CSS 变量可注入 | ✅ 推荐 |
  | uni-app(Vue) | 与 React 生态冲突,core 需重写 | ✗ |
  | 原生小程序 | 复用为零 | ✗ |
- UI 组件:Taro 端用 **NutUI-React(T京东,React 版)** 并以 @yyc3/theme CSS 变量覆盖主题;或自建 8-10 个核心件(Button/Card/List/Form/Steps/Popup)对齐 ui 件 API
- 可直接复用:`@yyc3/core` 的 types/api-client/营业日/离线队列;页面=05 文档 B1–B4(注册绑定/扫码签到签退/个人主页/我的流水)
- 注意:Taro 包放入 `apps/app-mp-artist`(build 产物 weapp);微信基础库 ≥2.20;扫码/定位原生 API 走 Taro

### 3.4 桌面端(可选,收银大屏)
- 若需:沿用 app-web-full 的 Electron 双出模式(electron-builder 三平台);包厢状态大屏 + 到店提醒弹窗
- MVP 不做(PWA 已覆盖收银场景)

### 3.5 移动原生 App(暂缓)
- PWA 已满足(添加到主屏/推送/离线);仅当需要应用商店分发/后台定位严格后台时,用 **Capacitor** 包同一 Web 工程——保留决策点,不预先投入

## 四、行动清单(落地步骤)

1. **挂工作区**:DeepStack-Matrix 内 `apps/app-leisure-web`(复制 app-web-full 骨架改名);pnpm install 验证 allowBuilds
2. **主题接入**:@yyc3/theme 引入;若 LeisureManage 需要独立品牌色,在 theme 增加子命名空间(不动全局令牌)
3. **页面脚手架**:按 05 文档 A1–A26 生成路由表(react-router 7)+ Sidebar 菜单注册(shell NavRegistry)
4. **PWA 打开**:迁 manifest/usePWAManager/InstallPrompt 三件;Lighthouse PWA≥90 验收
5. **小程序启动**:新建 `apps/app-mp-artist`(Taro4+React+TS);core 以 `pnpm workspace:*` 引入;NutUI 主题对齐
6. **共享领域包**:建议新增 `packages/leisure-core`(营业日/台费计算/流水类型/API client)——Web 与 Taro 共同 import,单源实现(这是双端一致性的关键)
7. **后端**:services 目录或独立仓;OpenAPI 生成各端 client

## 五、风险与说明

- @yyc3/ui 为"internal 源码直出"(exports 指向 src/*.tsx):要求消费端同为 React+Tailwind 管道;**Taro 端不可直接引 DOM 件**,仅引 core/theme
- pnpm 12 的 allowBuilds/security overrides 为仓库级:新增依赖需过一遍台账纪律(这是 YYC3 既有治理,继承即可)
- hotel-engines 属业务参考件:销售经理 AI 客服若做,优先抽其 voice-service/knowledge-base 模式而非直接依赖
- Taro 4 React 版对 React 19 支持以官方兼容表为准;若滞后,小程序端可锁 React 18(不影响 core 复用)
