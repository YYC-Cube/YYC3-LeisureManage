## 一、范围与目标

覆盖 Owner 需求五要素:**所有岗位 · 业绩提成 · 员工奖惩 · 所有金额/费用类目 · 分账目标三维(岗位/部门/人员)**,支持**金额、比例、支付方式**三类设定。定位:III-B 经营增值批次核心模块(008/009 规划承接;**S1-S4+深化 II 已于 2026-11-04 全部上线**,见 §五)。与既有底座衔接——

- **条线/部门/汇报线**:artist.line(SELL/RESOURCE,2026-11-04 已落列)+ department 树 + admin_user.managerId——分账对象与归集维度直接复用
- **资金底座**:关房结算 ROOM_SETTLE 只增、台费流水只增、审批流(双人)、日切营业日——计提与结算沿用同一纪律
- **资源经理线**:资源经理档案(复刻销售经理档案,已上线)自动纳入分账可选部门/分组

## 三、领域模型(草案)

### 3.1 类目(Category,分账触发源)

| 类目(预置,可扩展) | 计提基数来源 | 说明 |
|---|---|---|
| 上钟业绩 | showSession.feeAmount(营业日日切后) | 销售经理/资源经理上钟时长费 |
| 房账消费 | room_session.totalAmount | 关房结算总额按参与人分摊 |
| 自点单 | self_order.totalAmount | 点单提成基数 |
| 台票销售 | ticket_txn type=BUY amount | 台票出售提成 |
| 充值业绩 | stage_fee_txn type=RECHARGE | 充值拉单业绩 |
| 手动调整 | 人工录入 | 奖惩/补贴/罚扣(正负) |

### 3.2 方案与规则

```
SplitPlan(分账方案)
  id/storeId/name(如「销售经理月度提成」)/category(类目)/status(DRAFT·ACTIVE·ARCHIVED)
  periodType(DAILY/WEEKLY/MONTHLY)/effectiveFrom/effectiveTo
SplitRule(规则项,挂在方案下)
  planId/岗位或条线(admin_title 或 artist_line 或 departmentId)
  calcType(PERCENT 比例 / FIXED 固定金额 / TIERED 阶梯)
  percent(比例,0-100×2 位)/fixedAmount/阶梯表 tierJson[{min,max,percent}]
  payMethod(CASH/TRANSFER/BANK/OFFSET 抵扣台费)/payCycle
  rewardType(REWARD 提成奖励 / PENALTY 奖惩扣罚)
SplitEntry(计提记录,只增)
  planId/ruleId/ userId(分账对象)/line/departmentId/ baseAmount(基数)/amount(计提额)
  businessDate/refType+refId(溯源到 session/room_session/txn)/status(ACCRUED→CONFIRMED→PAID)
  payMethod/payRef(支付凭证号)/confirmedBy/paidAt
```

**红线沿用**:SplitEntry 只增不改(冲正=反向条目);全部显式 store_id;计提按营业日快照(规则改不影响已计提);复核走既有 approval(双人)。

### 3.3 闭环

```
方案配置(DRAFT→ACTIVE)
  → 日切 job 追加计提步:按 ACTIVE 方案×类目基数逐规则算额 → SplitEntry(ACCRUED)
  → 周期结算单:按 payCycle 汇总 ACCRUED → 结算单(人/期/金额/支付方式)
  → 复核(审批流,≠制单人)→ CONFIRMED
  → 支付确认(线下发放+凭证号)→ PAID;OFFSET 模式可直连台费冲抵(生成 REVERSE/RECHARGE 流水,维持只增)
  → 对账:计提合计 vs 结算合计 vs 支付合计 三向平衡(日切 job 扩展校验)
```

### 五·A 分账目标三维模型(岗位 ADMIN / 部门 DEPARTMENT / 人员 ARTIST)

| 维度 | targetScope | 对象来源 | 计提模式 | 结算/发放 |
|---|---|---|---|---|
| 人员 | `ARTIST` | artist(销售/资源经理,line 区分) | SESSION 自动计提+手动奖惩 | 结算单;OFFSET 可冲抵台费 |
| 岗位 | `ADMIN` | admin_user 岗位(admin_title) | 手动奖惩为主(主管抽成/团队管理岗) | 结算单;线下发放 |
| 部门 | `DEPARTMENT` | department 树 | 手动奖惩(团队激励/部门奖金;亦可按部门成员业绩人工汇总后录入) | 结算单=**部门池**(合计额),线下发放/负责人代领;**OFFSET 拒**(台费账户仅个人) |

> 与社区同类做法对齐:简道云提成方案「部门奖」、纷享销客提成「团队目标」、金蝶云星空「部门绩效池」均采用「部门池→内部二次分配」模式——本系统发放到部门口径为止,池内分配留线下(避免再造二级分配引擎;后续 III-C 可选做部门内拆分向导)。

### 五·C 收款闭环 × 结算闭环(2026-11-04 Owner 指令:同步分析完善)

**收款闭环(门店收钱)**:客人消费 → 房账(点单/送花/房费)→ 关房统一结算(settleType=CASH/WECHAT/ALIPAY/DOUYIN/FEE_DEDUCT——渠道走门店收费通道清单 DEFAULT_PAY_CHANNELS,门店可配 CUSTOM1-3)→ 台票抵扣(TICKET 只增 refSessionId 回链)→ 台费扣减(FEE_DEDUCT→ROOM_SETTLE 流水)→ 日切对账(recon+splitCheck)。
**结算闭环(门店分钱)**:计提(SESSION 自动+手动奖惩,≥阈值双人复核)→ 结算单(人/岗位/部门池;周期聚合 CONFIRMED)→ 支付确认(**结算方式=门店全部收付款渠道单源**:CASH/TRANSFER/BANK/WECHAT/ALIPAY/DOUYIN/CUSTOM1-3 + OFFSET 台费冲抵[仅个人])→ 凭证号(payRef 单笔填/CSV 批量导入)→ 三向对账(计提净额=已结=已付;日切 splitCheck 不平衡自动告警)。
**两环统一口径**:收款渠道与结算方式共用**渠道码单源**(大写码 ≤20 位,门店可配;OFFSET 为分账侧保留语义)。分账目标选择器(2026-11-04):姓名/部门/组别/电话任一项自动匹配(PersonPicker 统一选人器,首字母搜索);部门目标=部门池模式(合计额线下发放/负责人代领,池内二次分配留线下)。
**待完善(登记)**:① 门店渠道清单动态读取(store_config pay_channels → 结算下拉实时同步;现为静态全集);② 客人收款(房账结算)与销售经理到账(分账支付)的对冲视图(一单一览:该单收了多少/分了多少/差额);③ 部门池内部分配向导(III-C)。
