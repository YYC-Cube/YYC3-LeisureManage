## 二、模块实现规格(逐模块:入口→事务→审计)

### 2.1 auth
- `POST /auth/admin/login`:手机号+密码(Argon2id);连错 5 次锁 15 分钟(Redis 计数);JWT access 2h + refresh 7d;payload 含 `permCodes[] / storeIds[]`
- `POST /auth/wx/login`:code2session → openid;命中 artist.wechat_openid 发 token;未命中返回 `NEED_BIND + bindToken(15min)`
- `POST /auth/wx/bind`:校验腰牌号/手机号匹配档案 → **唯一性检查**:openid 已绑他店 → 按 `TRANSFER_MODE`(manual/auto)建转移工单或直接转移(事务:旧店 status=TRANSFERRED + audit + 新店绑定)
- 敏感操作再验证:`POST /auth/reverify`(密码)→ 5 分钟一次性 stamp;手动扣费/转移/代下钟必须携带

### 2.2 artist
- 创建/更新:腰牌号唯一冲突 → `LeisureError(40901)`;身份证号经 KMS 加密落 `id_card_no_enc`;照片直传 OSS(服务端签发上传凭证),仅存 key
- 删除:有 fee/ticket/session 流水 → `40906`;无流水亦为软删(deleted_at)
- 转移:工单(双店管理员确认)→ 事务:旧店 `status=TRANSFERRED` + `deleted_at` + audit + wechat_openid 迁移
- 批量设置:一个事务内逐条审计(非批量审计一条)

### 2.3 attendance
- 签到:`leisure-core.resolveBusinessDate` 算营业日 → 校验当日未签 → 落 attendance_report(geo 可空,`checkin_geo_ok` 标记)→ Redis `ZADD artist:status:{store} <ts> <artistId:status=1>`
- 签退:`millisSinceBusinessDayStart` 或 (now - report_time) < 配置 N 分钟 → `40905`;更新签退字段+定位
- 实时看板:`ZRANGE` 聚合计数 + 名单(10s 客户端轮询;预留 WS)
- 明细/汇总:SQL 聚合(group by group_id, supervisor_name, type);汇总列固定 10 列(陪宴/签到/私事/早退/迟到/例假/其他/未报备/签退/合计)
- 补打卡:`operator` 落审计;`source=MANUAL`

### 2.4 session + stage-fee(核心事务)
```
POST /sessions/start(事务):
  1. 读 artist + 当日已完成场次计数 + 进行中场次
  2. assertCanTakeSession(leisure-core)→ 违规抛 40904/400
  3. INSERT show_session(start_at, room 快照)
  4. Redis 状态→ON_STAGE / CROSS
  5. audit:SESSION_START

POST /sessions/{id}/finish(事务):
  1. 规则解析:resolveStageFeeRule(rules 快照, levelId, roomTypeId)
     —— 规则快照取「start_at 时点」的规则版本(规则表带有效期的历史表或 updated_at 过滤)
  2. calcSessionFee(FLAT;minDuration=档案 sameRoomMinMinutes)
  3. UPDATE session(end_at, duration, fee_amount)
  4. INSERT stage_fee_txn(SESSION_DEDUCT, -fee, ref_session_id)
  5. 若艺人持有效台票且业务开关开:提示可用台票(核销走 /tickets/use)
  6. Redis 状态→CHECKED_IN;audit
```
- 充值:CASH 即事务落 RECHARGE 流水;DOUYIN 走预下单(pay_order 表)→ 回调落流水(**幂等键+渠道单号唯一**)
- 手动扣费:备注必填(400);金额≥阈值 → approval(PENDING)→ 审批通过事务落流水;余额允许负(对齐实测"未收款"概念),负值报表标红

### 2.5 payment(支付渠道,v1.1 裁决:原 integration 主系统适配废止)
- `CASH`:现金记账(默认渠道,充值事务内直接落 RECHARGE 流水)
- `DouyinPay`:下单(pay_order)→ 回调落流水(幂等:渠道单号唯一)→ 对账 job(渠道账单 vs pay_order/流水比对)
- `OpenApi`(生态预留,默认关闭):门店/房型/流水只读查询能力,供连锁总部视图或第三方分析接入;按 storeId 灰度
- 渠道熔断:连续失败 N 次 → 熔断 10 分钟,事件本地排队(openapi_event 表)补投

## 三、定时任务(jobs)

| 任务 | cron | 职责 |
|---|---|---|
| day-cut-summary | 每日 08:05 | 按营业日物化 daily_summary(各域汇总)+ 校验明细和=汇总 |
| ticket-expire | 每日 08:10 | 有效期到期台票批量写 EXPIRE 流水 |
|Douyin-reconcile | 每日 09:00 | 渠道账单 vs pay_order/fee 流水比对,差异表 |
| backup-verify | 每日 03:00 | 备份完成校验+恢复抽检告警 |
| archive-monthly | 每月 1 日 | 36 个月前流水迁归档表 |
| realtime-snapshot | 每 5 分钟 | 实时状态快照(供离线审计) |

实现:BullMQ(Redis)或接入现有 XXL-Job;全部任务**幂等**(重跑不重复写),有跑批日志表。

## 五、横切规格

- **异常映射**:`LeisureError.code` → HTTP;映射表:40901→409, 41201→202(Accepted+审批单), 42901→429, 其余 400/404/403;`code` 原样入响应体(四端一致判断)
- **幂等**:写接口 `Idempotency-Key` → `idempotency_keys` 表(store, key, response 快照, 24h TTL 唯一索引);拦截器先查后放
- **审计**:audit.interceptor 对 `@Audit(action)` 标注方法记录 before/after(读改前快照);audit_log 只允许 INSERT(优雅:独立 DB 账号)
- **分页**:cursor 或 page/pageSize(≤200);列表响应含 `total`
- **OpenAPI**:Nest Swagger 生成 `/docs`;各端 client 由 leisure-core 或 openapi-typescript 生成
- **可观测**:pino 结构化日志(traceId 贯穿)+ Prometheus `/metrics` + Sentry;慢查询 >200ms 告警
- **灰度**:按 storeId 灰度开关(feature flag 表)
