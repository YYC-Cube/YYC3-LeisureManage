## 2. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 小程序 | **Taro 4(React)+ NutUI-React(主题对齐 @yyc3/theme)** | 扫码/定位/登录;JSX 同源,可直接复用 @yyc3/core 领域逻辑 |
| 管理后台 | **React 19 + Vite 8 + @yyc3/ui(shadcn/radix 49 件)+ @yyc3/shell + ECharts** | 复用 DeepStack-Matrix 资产;报表矩阵(报备汇总 9 状态列) |
| 后端 | NestJS(TypeScript) 或 Spring Boot | 单店起步模块化单体;按域分 module 可拆微服务 |
| ORM | Prisma / MyBatis-Plus | 流水表分区与批量写入友好 |
| DB | MySQL 8(InnoDB,utf8mb4) | 事务+分区;utf8mb4 兼容表情昵称 |
| 缓存 | Redis | 实时状态看板(色点统计)+会话+分布式锁 |
| 文件 | OSS(私有读)+服务端 AES 加密 | 身份证/照片合规 |
| 任务 | XXL-Job / Bull | 营业日切、对账、归档 |
| 部署 | Docker Compose 单机 → K8s(连锁期) | 起步成本最低 |

| 模块 | 职责 | 关键规则 |
|---|---|---|
| auth | 小程序 code2session、管理端账号、RBAC、职务-功能映射 | 微信绑定唯一性校验 |
| artist | 档案 CRUD、组别、等级、标签、腰牌号唯一、软删、批量设置、跨店转移 | 转移需确认+日志 |
| attendance | 报备签到签退(定位)、补打卡、明细/汇总、实时状态(Redis ZSET) | 签到 N 分钟后才可签退(可配) |
| session | 上钟场次:起表/下表/串台校验、时长与台费计算、上下钟检索 | 档案限制字段前置校验 |
| stagefee | 台费规则 CRUD、充值(现金/抖音)、扣费流水、手动扣费(审批)、流水查询汇总 | **流水不可变**;冲正反向流水 |
| ticket | 台票规则、购买、核销、双流水 | 同 stagefee 红线 |
| order | 艺人订单查询(集成层取数)、评价回收与检索 | 只读为主 |
| report | 10 张艺人报表(对齐 PC)+导出 | 营业日口径 |
| payment | 支付渠道:抖音支付下单/回调/对账(现金为默认渠道);开放 API 生态预留 | 渠道回调幂等(单号唯一);不与任何第三方 KTV 主系统对接 |
| audit | 全部敏感操作审计(谁/何时/何事/前后值) | 不可改,追加写 |
| notify | 短信/订阅消息:签到提醒、审批、到期 | — |

## 4. 关键设计

### 4.1 营业日(Business Date)
- 配置日切时刻(默认 08:00)。所有流水写入时冗余 `business_date` 字段(非按 created_at 推算),日切任务仅做汇总物化。
- 报表/汇总一律按 `business_date` 过滤——与实测系统口径一致(页面默认 `2026-10-31 08:00 至 2026-11-01 08:00`)。

### 4.2 实时状态看板
- Redis: `artist:status:{storeId}` ZSET(member=artistId, score=状态码 0空闲/1签到/2上钟/3串台/4被选中)。
- 状态机由事件驱动:报备签到→1;上钟起表→2/3;下钟→1;被点台→4。
- 页面轮询 10s 或 WebSocket 推送。

### 4.3 台费计算(方案甲 2026-11-01 裁决)
```
session 结束 → fee = 规则快照核算(HOURLY×进位阈值 / FLAT)
           → 计入房账(room_session.room_fee;不落流水、无余额防线)
           → 房关房结算 → 台费抵扣部分写 stage_fee_txn(type=ROOM_SETTLE);现金部分直接收款
串台: 每房各生成一条 session,fee 各自计算;校验档案.max_cross_rooms
```

### 4.4 流水不可变与冲正
- `stage_fee_txn` / `ticket_txn` 无 UPDATE/DELETE 权限( revoke );更正 = 反向类型流水 + 关联原流水 id。
- 手动扣费:金额 ≥ 阈值(默认 500)→ 生成审批单,审批通过才落流水。

### 4.5 微信绑定唯一性
- `artist.wechat_openid` 唯一索引;绑定流程:扫码 → 拉档案 → 若 openid 已存在他店:
  - 配置=人工(默认):提示并生成跨店转移工单,双方店管理员确认后执行转移+审计
  - 配置=自动(对齐实测):转"已转移"态 + 删除日志

### 4.6 支付渠道与开放 API(v1.2 裁决:主系统集成废止)
```
payment 模块 = 渠道适配(独立运营,无主系统依赖)
  ├─ CASH:现金记账(默认渠道,充值即落流水)
  ├─ DOUYIN:抖音支付下单(pay_order)→ 回调落流水(幂等:渠道单号唯一)→ 对账 job
  └─ 开放 API(生态预留):门店/房型/流水查询能力,供连锁总部视图或第三方分析接入
```

## 5. 部署拓扑(起步)

```
单云主机 4C8G:
  docker compose: nginx / app / mysql / redis / jobs
  OSS: 阿里云(同地域)
  备份: mysqldump 每日全量 + binlog 增量 → OSS;保留 30 天
连锁期: K8s + 读写分离 + 流水表按月分区归档
```
