## 二、补齐表 DDL(03 未含部分)

```sql
-- 绑定历史(跨店唯一性的全量留痕;自动/人工转移都要写)
CREATE TABLE wechat_bind_log (
  id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  openid VARCHAR(64) NOT NULL,
  artist_id BIGINT UNSIGNED NOT NULL,
  store_id BIGINT UNSIGNED NOT NULL,
  action VARCHAR(16) NOT NULL COMMENT 'BIND/UNBIND/TRANSFER_IN/TRANSFER_OUT/AUTO_DELETE',
  prev_store_id BIGINT UNSIGNED NULL,
  prev_artist_id BIGINT UNSIGNED NULL,
  mode VARCHAR(8) NOT NULL COMMENT 'MANUAL/AUTO',
  operator_id BIGINT UNSIGNED NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  KEY idx_openid (openid),
  KEY idx_artist (artist_id)
) COMMENT '微信绑定历史(只增)';

-- 跨店转移工单(TRANSFER_MODE=manual 时)
CREATE TABLE transfer_workorder (
  id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  openid VARCHAR(64) NOT NULL,
  from_store_id BIGINT UNSIGNED NOT NULL,
  from_artist_id BIGINT UNSIGNED NOT NULL,
  to_store_id BIGINT UNSIGNED NOT NULL,
  to_badge_no VARCHAR(32) NULL COMMENT '目标店新腰牌号(可重排)',
  status VARCHAR(16) DEFAULT 'PENDING' COMMENT 'PENDING/FROM_OK/TO_OK/DONE/REJECTED/CANCELLED',
  payload JSON COMMENT '原档案快照(转移内容)',
  created_by BIGINT UNSIGNED,
  decided_by BIGINT UNSIGNED NULL,
  decided_at DATETIME NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  KEY idx_status (status), KEY idx_openid (openid)
) COMMENT '跨店转移工单(双店确认)';

-- 三方支付单(抖音/扩展)
CREATE TABLE pay_order (
  id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  store_id BIGINT UNSIGNED NOT NULL,
  business_date DATE NOT NULL,
  channel VARCHAR(16) NOT NULL COMMENT 'DOUYIN/…',
  out_trade_no VARCHAR(64) NOT NULL COMMENT '我方单号',
  channel_trade_no VARCHAR(64) NULL COMMENT '渠道单号',
  amount DECIMAL(10,2) NOT NULL,
  status VARCHAR(16) DEFAULT 'CREATED' COMMENT 'CREATED/PAYED/FAILED/REFUNDED/CLOSED',
  artist_id BIGINT UNSIGNED NULL,
  biz_type VARCHAR(16) COMMENT 'FEE_RECHARGE/TICKET_BUY',
  biz_ref_id BIGINT UNSIGNED NULL COMMENT '成功后落的流水id',
  raw_notify JSON NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  paid_at DATETIME NULL,
  UNIQUE KEY uk_out (out_trade_no),
  UNIQUE KEY uk_channel (channel, channel_trade_no),
  KEY idx_store_date (store_id, business_date)
) COMMENT '三方支付单(回调幂等锚点)';

-- 幂等键(写接口去重,24h TTL)
CREATE TABLE idempotency_keys (
  id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  store_id BIGINT UNSIGNED NOT NULL,
  idem_key VARCHAR(80) NOT NULL,
  path VARCHAR(128) NOT NULL,
  response_snapshot JSON,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_key (store_id, idem_key, path),
  KEY idx_created (created_at)
) COMMENT '幂等键(过期清理job)';

-- 开放API/渠道事件队列(熔断或异步投递时的本地排队;v1.1 裁决:原主系统集成事件废止)
CREATE TABLE openapi_event (
  id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  store_id BIGINT UNSIGNED,
  event_type VARCHAR(32) NOT NULL COMMENT 'PAY_NOTIFY/OPENAPI_PULL/…',
  payload JSON NOT NULL,
  status VARCHAR(16) DEFAULT 'PENDING' COMMENT 'PENDING/SENT/FAILED/DEAD',
  retry_count INT DEFAULT 0,
  last_error VARCHAR(500) NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  sent_at DATETIME NULL,
  KEY idx_status (status, created_at)
) COMMENT '开放API/渠道事件队列';

-- 角色多店范围
CREATE TABLE role_store (
  role_id BIGINT UNSIGNED NOT NULL,
  store_id BIGINT UNSIGNED NOT NULL,
  PRIMARY KEY (role_id, store_id)
) COMMENT '角色-门店数据范围';

-- 跑批日志
CREATE TABLE job_run_log (
  id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  job_name VARCHAR(64) NOT NULL,
  business_date DATE NULL,
  status VARCHAR(16) NOT NULL COMMENT 'RUNNING/OK/FAILED',
  stats JSON NULL,
  started_at DATETIME NOT NULL,
  finished_at DATETIME NULL,
  error VARCHAR(1000) NULL,
  KEY idx_job_time (job_name, started_at)
) COMMENT '定时任务跑批日志(幂等重跑依据)';
```

## 三、迁移策略(Prisma Migrate)

### 3.1 流程
```
prisma migrate dev --name xxx      # 本地生成 migration SQL(进 git review)
prisma migrate deploy             # staging/prod 只应用不生成
```
- 迁移文件**禁止手改**;大表变更走「expand → dual-write → backfill → contract」四步
- 每次迁移附带回滚说明(手写 `-- ROLLBACK:` 注释段)

### 3.2 关键迁移红线
1. `stage_fee_txn / ticket_txn / attendance_report / audit_log`:**只加列不删列不改列**;列废弃=`deprecated_*` 重命名+停写
2. 台费规则变更:不改旧行——`stage_fee_rule` 加 `valid_from DATETIME`,历史计算按 `show_session.start_at` 时点取版本(配合 03「快照」策略)
3. 首次部署 seed:门店/房型/等级(技师)/组别/角色与功能码/系统配置项——见 §5

## 四、索引 / 分区 / 归档 / 容量

### 4.1 索引清单(高频查询 → 索引)
| 查询 | 索引 |
|---|---|
| 台费流水(营业日区间+组别+销售经理) | `idx_store_date` + `idx_artist_date`;keyword 走 artist 冗余列(stage_name/badge_no 冗余到 txn,避免join) |
| 上下钟(三维 Tab) | `idx_store_date` + `idx_artist`;包厢 Tab → 补 `KEY idx_room (store_id, room_id, start_at)` |
| 报备明细(日+组+状态) | `idx_store_date` + `(store_id, group_id, type, business_date)` |
| 看板计数 | Redis 承担;DB 兜底 group by |
| 幂等去重 | `uk_key(store_id, idem_key, path)` |

### 4.2 分区与归档
- `stage_fee_txn / ticket_txn / show_session / attendance_report`:按 `business_date` RANGE 月分区(Prisma 不管理分区 → migration 内裸 SQL `ALTER TABLE … PARTITION BY RANGE`);查询强制带 business_date 走分区裁剪
- 归档:>36 个月迁 `*_archive` 同构表(月分区内直接 `RENAME` 分区交换);归档表只读
- `audit_log`:按月分区,保留 3 年,哈希链(每行含 prev_hash)防篡改

### 4.3 容量估算(单店 200 销售经理 · 日均 400 场次)
| 表 | 行/月 | 大小/月(估) |
|---|---|---|
| show_session | ~1.2 万 | ~5 MB |
| stage_fee_txn | ~1.5 万 | ~4 MB |
| attendance_report | ~0.6 万 | ~2 MB |
| audit_log | ~5 万 | ~25 MB |
| 合计(全表) | <10 万/月 | **<50 MB/月 → 年 <600 MB**,单库 5 年无压力;连锁 50 店 <30 GB/年(仍可单实例+读写分离) |

## 六、备份与容灾

| 项 | 策略 |
|---|---|
| 全量备份 | 每日 03:30 mysqldump(single-transaction)→ OSS;保留 30 天 |
| 增量 | binlog ROW 实时推 OSS;保留 7 天 |
| RPO / RTO | ≤5 分钟 / ≤1 小时(全量+binlog 回放) |
| 演练 | 季度恢复演练(job backup-verify 抽表校验行数) |
| 双活预留 | 连锁期:同城从库半同步 + ProxySQL 读写分离 |
