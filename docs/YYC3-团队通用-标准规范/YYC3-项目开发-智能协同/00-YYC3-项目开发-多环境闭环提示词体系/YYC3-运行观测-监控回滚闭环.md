## 一、文档定位

- **环境**：E3 生产运行 / E4 灾备回退
- **阶段**：observe → rollback → verify
- **适用**：上线后观测、日常巡检、故障处置、主备切换、数据事故
- **不适用**：功能开发（02）、版本发布（05）

> **处置顺序**：先止血（回退/切流/降级）→ 再定位 → 再修复 → 最后复盘。禁止在故障窗口内"边猜边改"。

## 二、事故判级与目标

| 级别 | 定义 | 示例 | 响应 |
| ---- | ---- | ---- | ---- |
| **L1** | 全站不可用 | 域名/边缘/隧道全断；API 全 5xx | 立即切流/回退，通报全员 |
| **L2** | 功能域不可用 | 登录不可用；收银/开房失败；对账中断 | 限时止血，关闭受影响入口 |
| **L3** | 单点体验 | 单账号异常、单页面报错、盒子语音失败 | 记录并排期修复 |

| 指标 | 目标 | 说明 |
| ---- | ---- | ---- |
| RTO | ≤ 15 分钟 | 就地切流为主 |
| RPO | ≤ 24 小时 | 每日 `pg_dump` + WAL |
| 观测窗口 | 发布后 ≥ 30 分钟 | 结束时须有结论 |

## 三、观测维度（五维落地）

| 维度 | 观测项 | 数据来源 |
| ---- | ------ | -------- |
| 可用性 | 域名可达、静态 200、API 鉴权响应 | curl / 边缘日志 |
| 性能 | 首屏耗时、接口 P95、静态体积 | 浏览器 / nginx |
| 业务 | 登录成功率、开房/签退失败数、自点单失败码、对账差异 | API 日志 + 只读 SQL |
| 安全 | 异常登录、越权 403 峰值、密钥/配置异常 | 审计日志 |
| 关联 | 隧道状态、主备复制、备份完成、证书到期 | launchd / frp / pg / LE |

> **现状缺口（P1）**：仓库未见独立 `/api/v1/health` 端点。当前只能以业务接口响应判断存活。建议新增轻量健康端点，并区分 liveness / readiness。

## 四、主提示词（可复制）

```text
【0 角色】
你是 YYC³ 的生产事件指挥官 Agent。你遵循"先止血、后定位、再修复、终复盘"。你不猜测、不隐瞒、不在未确认影响面前扩大操作。

【1 上下文】
- 环境：E3 生产 / E4 灾备
- 端：{Web/H5/小程序/API/DB/边缘/隧道}
- 阶段：{observe/rollback/verify}
- 事件级别：{L1/L2/L3}
- 时间线起点：{首次异常时间}
- 已知变更：{最近发布/迁移/配置变更 + 时间}
- 当前 upstream：{8802/8801}
- 已锁定记忆：{应急预案、回退位、基线}

【2 目标】
在最短时间内恢复服务并保留证据，给出根因假设与后续行动。
非目标：不在故障窗口内做无关优化；不掩盖未验证的结论。

【3 约束】
硬约束：
1. 先记录时间线与证据，再动生产；
2. 回退/切流前必须确认目标实例与命令（双人复核更佳）；
3. 数据事故必须先快照，禁止整库回滚覆盖线上；
4. 账务更正只走 REVERSE 反向流水，禁止 UPDATE/DELETE；
5. 任何操作必须可回退；不可回退操作视为 D 级，禁止；
6. 结论必须区分"已证实"与"待确认"。
软约束：优先最小影响面操作（关入口 > 切流 > 回退 > 重启）。
红线：无证据重启、同时对多层做变更、删除日志、擅自提升备库为主 → 立即停止。

【4 思考协议】
1. 事实：告警/症状、首次时间、影响面、最近变更、当前实例状态；
2. 假设：≤3 条（变更引入 / 依赖故障 / 容量与资源 / 外部链路）；
3. 反证：用日志与探测交叉排除（如 502 来自边缘还是 API）；
4. 影响：五维（恢复时间、影响端、数据一致性、事件链、依赖）；
5. 裁决：止血动作 + 置信度 + 待确认。

【5 技能路由】
- 浏览器复现：webapp-testing / agent-browser（只读操作优先）；
- 结构化评审：MCP yyc3_code_review（定位代码级根因）；
- 性能分析：MCP yyc3_performance_analyzer（延迟/资源）；
- 安全事件：security-best-practices（显式请求）+ 合规流程。

【6 动作】
1. 记录：时间线、症状、影响端、最近变更；
2. 止血：按影响面选择 关入口/切流/回退/重启；
3. 验证止血：关键链路恢复证据；
4. 定位：四层（浏览器/边缘/API/DB）+ 日志；
5. 修复：最小改动，走发布环；
6. 复盘：输出事件闭环卡与改进项。

【7 输出】
- 事件闭环卡（§七）
- 时间线（T0 起，逐条操作与结果）
- 影响评估（级别/端/时长/数据）
- 根因：已证实 / 待确认
- 止血与恢复证据
- 后续行动 P0/P1/P2
- next_hook（复盘归档）

【8 自检】
DoD 逐条核对；"已恢复"必须有验证证据与观测窗口结论。
```

## 五、故障树与处置要点

| 故障域 | 判别 | 止血 | 恢复 |
| ------ | ---- | ---- | ---- |
| DB 主库 | `/api/v1` 全面 5xx；`pg_isready` 失败 | 切 NAS 8801 + 关闭写入口 + 公告只读 | 修复主库 → 切回 8802 |
| API 实例 | 单实例不可达；KeepAlive 拉起失败 | 切另一实例 | 查 `/tmp` 日志与启动参数 |
| 隧道 | 8802/8801 断 | 重启隧道服务 | 确认 sshd/网络/frp |
| 边缘 | 502/504、证书异常 | 重启容器 / 直连内网（仅内网） | 修 nginx / 续证书 |
| 数据 | 误删、账务差异 | 快照 + 关写入口 | 临时库回灌 / REVERSE 流水 |
| 安全 | 异常登录、入侵嫌疑 | 断公网入口 + 保留日志 | 走安全事件流程 |

## 六、回滚决策矩阵（建议阈值，需与运维确认）

| 信号 | 建议动作 | 说明 |
| ---- | -------- | ---- |
| 5xx 比例持续高于基线且影响登录/收银 | 立即回退 | 先恢复可用性 |
| 关键链路成功率下降 > 20%（窗口 10 分钟） | 回退或切流 | 以基线为准 |
| 数据写入异常/账务不一致 | 关闭写入口 | 保护数据优先 |
| 单页面/单账号问题 | 不回退 | 记录并修复 |
| 资源耗尽（连接/磁盘） | 扩容或降级 | 先止血 |
| 迁移后旧代码报错 | 回退代码（结构兼容） | 只加列保证兼容 |

> 阈值不是现网既定告警规则；落地前需与运维确认基线并写入监控系统。

## 七、事件闭环卡示例

```yaml
loop_card:
  loop_id: "LM-E3-INCIDENT-20261103-05"
  env: E3
  ends: [T1, T4]
  stage: rollback
  baseline: "tag v0.1.4；upstream 8802；事件 T0=10:42"
  verdict: CONDITIONAL
  evidence:
    - cmd: "边缘日志与 API 日志比对"
      result: "502 来自 upstream 8802 超时；API 进程存活但请求堆积"
      artifact: "/tmp/leisure-api-prod.err 10:41–10:44"
    - cmd: "切流 8802→8801 + nginx -s reload"
      result: "登录恢复 200；错误率回落"
      artifact: "边缘 access log 10:47"
  deviations:
    - plan: "先定位再切流"
      actual: "先切流后定位"
      reason: "L2 级别，优先止血"
  risks:
    p0: []
    p1: ["无健康端点，实例状态判断滞后"]
    p2: ["告警阈值未系统化"]
  pending_confirmation: ["API 请求堆积是否与新版本发布相关"]
  memory_writes:
    pinned: ["事件：8802 超时→切 8801 恢复；根因待定位"]
    session: "2026-11-03-incident/summary.md"
    state: "E3/verify"
  next_hook:
    env: E5
    stage: archive
    first_action: "基于事件卡输出复盘报告与改进项"
    required_memory: ["08 裁决归档环", "007 应急预案"]
    rebuild_order: ["00", "06", "08"]
```

## 八、DoD（事件闭环验收）

- [ ] 时间线完整（T0 起，含操作与结果）
- [ ] 影响级别、端、时长、数据范围已评估
- [ ] 止血动作有验证证据
- [ ] 根因区分"已证实/待确认"
- [ ] 观测窗口已结束并有结论
- [ ] 数据事故有快照与回灌记录
- [ ] 账务更正走反向流水（如涉及）
- [ ] 改进项分级并指定负责人/期限
- [ ] 事件闭环卡与 next-hook 已产出

## 九、失败模式与正反例

| 反例 | 问题 | 正例 |
| ---- | ---- | ---- |
| 无证据反复重启 | 掩盖根因、延长故障 | 先看日志与实例状态 |
| 同时改边缘+API+DB | 无法归因 | 单变量止血 |
| 整库回滚覆盖线上 | 丢失当日真实数据 | 快照 + 临时库 + 精准回灌 |
| 账务直接 UPDATE | 审计链断裂 | REVERSE 反向流水 |
| "观察一下"没有窗口 | 故障复发无判据 | 明确 30 分钟窗口与指标 |
| 删除错误日志 | 无法复盘 | 保留并归档 |
