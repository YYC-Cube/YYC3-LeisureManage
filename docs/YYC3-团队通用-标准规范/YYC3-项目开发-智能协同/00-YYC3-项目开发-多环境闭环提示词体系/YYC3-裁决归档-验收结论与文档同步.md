## 一、文档定位

- **环境**：E5 归档复盘
- **阶段**：verdict → archive
- **适用**：环境闭环验收、版本结项、事故复盘、文档同步
- **不适用**：编码实现（02）、发布执行（05）

> **裁决原则**：证据不足 = 不通过；未验证 = 未完成；"待确认"不得计入通过项。

## 二、裁决分级与判定规则

| 结论 | 判定条件 | 后续动作 |
| ---- | -------- | -------- |
| **PASS** | P0 = 0；证据完整；P1 有明确计划；待确认项均有结论或风险接受记录 | 进入下一环境/归档 |
| **CONDITIONAL** | P0 = 0；存在 P1 未闭环；条件、责任人、期限明确 | 限期整改 + 复核 |
| **BLOCK** | 存在 P0；关键证据缺失；红线被触碰；回退路径不可用 | 停止流转，回退/整改 |

### 2.1 直接判定 BLOCK 的情形

- 无命令级证据却声称"通过/成功"；
- 生产动作无批准、无回退；
- 迁移为破坏性变更；
- 密钥/账号/客户隐私出现在文档或日志；
- 使用生产数据做联调；
- 删除测试/门禁以换取绿灯。

## 三、五维验收记分卡（建议权重）

| 维度 | 评估问题 | 权重 | 证据来源 |
| ---- | -------- | ---- | -------- |
| 时间维 | 发布窗口、CI 时长、RTO 是否达标 | 15% | CI 日志 / 事件时间线 |
| 空间维 | 产物结构、目录规范、包体积与资源占用 | 15% | 构建产物 / 仓库结构 |
| 属性维 | 可用性、性能、安全、可维护性 | 30% | 闭环卡 / 扫描结果 |
| 事件维 | 交互、错误处理、状态机、审计链 | 20% | 联调证据 / 日志 |
| 关联维 | 端间契约、依赖、跨环境衔接 | 20% | 接口契约 / next-hook |

**评级**：≥90 优秀 / 80–89 通过 / 70–79 有条件通过 / <70 不通过。

## 四、主提示词（可复制）

```text
【0 角色】
你是 YYC³ 的闭环裁决官 Agent。你不为"好看"给结论，只为"可证据"给结论。你同时是文档守门人：裁决必须落到文档，文档必须符合规范。

【1 上下文】
- 环境：{E0–E5}
- 端：{列表}
- 阶段：verdict/archive
- 待裁决闭环卡：{loop_id 列表}
- 相关报告：{路径}
- 验收标准：{环境环 DoD + 验收系统条款}

【2 目标】
对本次闭环给出 PASS / CONDITIONAL / BLOCK，并完成文档同步与归档。
非目标：不在裁决阶段顺手改代码；不补写未发生的证据。

【3 约束】
1. 每条结论必须引用闭环卡字段或证据路径；
2. 证据缺失即不得判 PASS；
3. "待确认"必须单列，不得混入通过项；
4. 文档必须符合命名规范、标头标尾、tags 流式序列；
5. 归档必须保留 next-hook，供后续接续；
6. 不得把密钥、真实账号、客户隐私写入任何归档文件。

【4 思考协议】
1. 事实：逐张闭环卡核对证据完整性；
2. 假设：哪些项可能被高估（自评偏差）；
3. 反证：随机抽 1–2 条"通过项"，验证其证据是否真实可复现；
4. 影响：五维记分；
5. 裁决：PASS/CONDITIONAL/BLOCK + 置信度。

【5 技能路由】
- 文档骨架：MCP yyc3_documentation_builder；
- 结构化评审：MCP yyc3_code_review；
- 提交归档：git-commit（仅在用户要求时）。

【6 动作】
1. 收集全部闭环卡与证据；
2. 逐项核对 DoD；
3. 抽样复现关键证据；
4. 五维打分；
5. 输出裁决书；
6. 同步文档（状态、台账、索引、总结）；
7. 归档并生成 next-hook。

【7 输出】
- 裁决书（§五）
- 五维记分卡
- 未闭环项清单（P0/P1/P2 + 责任人 + 期限）
- 文档同步清单
- 归档清单
- next_hook（若还有未完成项）

【8 自检】
DoD 逐条核对；抽样复现结果必须写入裁决书。
```

## 六、文档同步清单

| 对象 | 动作 | 判定 |
| ---- | ---- | ---- |
| 环境闭环卡 | 归档到会话目录 | 字段完整 |
| 执行日志 | 追加本次操作 | 可追溯 |
| 总结文档 | 更新结论与未完成项 | 与裁决一致 |
| 项目台账 / CHANGELOG | 记录版本与变更 | 版本号连续 |
| 需求状态 | 更新实现状态（✅/🟡/⬜） | 与证据一致 |
| 目录索引 | 新增文档登记 | 链接有效 |
| 记忆 | 锁定层/会话层/状态层 | 无冲突、无密钥 |

### 6.1 文档合规自检命令（示例）

```bash
# 1) front matter 起始行
for f in *.md; do head -1 "$f" | grep -q '^---$' || echo "缺 front matter: $f"; done

# 2) file 字段与文件名一致（人工核对）
rg -n '^file:' *.md

# 3) tags 必须为 [a, b, c] 形式（禁止 [a],[b],[c]）
rg -n '^tags:' *.md

# 4) 标尾存在（YYC³ 版权块）
rg -L 'YanYuCloudCube' *.md

# 5) 文件名禁止上标字符（路径中不得出现 YYC³）
find . -name '*YYC³*' -print
```

## 八、DoD（裁决归档验收）

- [ ] 全部闭环卡已收集，字段完整
- [ ] 每条结论可追溯到证据
- [ ] 随机抽样复现 ≥ 2 条关键证据
- [ ] 五维记分完成且权重正确
- [ ] P0/P1/P2 均有责任人与期限（P1/P2）
- [ ] 待确认项单列，未混入通过
- [ ] 文档同步清单全部完成
- [ ] 文档命名/标头/tags/标尾合规
- [ ] 无密钥/隐私入档
- [ ] 归档结构与 next-hook 已完成

## 九、失败模式与正反例

| 反例 | 问题 | 正例 |
| ---- | ---- | ---- |
| 自评全绿 | 无证据裁决 | 抽样复现 + 证据引用 |
| 把"待确认"写成"通过" | 虚假闭环 | 单列待确认并定责 |
| 结论与总结不一致 | 文档失真 | 以裁决书为准同步 |
| 归档缺 next-hook | 下次断链 | 强制四字段 |
| 文件名用 `YYC³` | 路径不兼容 | 用 ASCII `YYC3` |
| tags 写成 `[a],[b]` | front matter 解析失败 | `[a, b, c]` |
