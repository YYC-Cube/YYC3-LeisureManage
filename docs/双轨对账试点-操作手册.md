# 双轨对账试点 · 操作手册

> 版本:v1.0(2026-11-01)|目标:与本店现用「智慧商家」并行 ≥14 天,每日四指标零差异后切换
> 后端已就绪:`GET /reports/recon`(查询)· `POST /reports/recon/legacy`(导入对侧日报,录后即时比对)

---

## 一、对齐口径(四指标,单营业日 08:00~次日 08:00)

| 指标 | 本系统(self) | 对侧(智慧商家)取数位置 |
|---|---|---|
| openCount 开房数 | room_session 当日总数(OPEN+CLOSED) | 包厢状态页「当日开房数」合计 / 日报表 |
| roomFee 时间费 | Σ上钟时间费(计入房账,方案甲) | 台费流水/上下钟汇总「计费小时×单价」合计 |
| orderTotal 点单额 | Σ self_order(房账挂账口径) | 订单列表「消费金额」合计(后买单口径一致) |
| checkedIn 签到人数 | attendance CHECKIN 当日人数 | 报备汇总「签到(人)」 |

## 二、每日流程(5 分钟)

1. **对侧取数**(智慧商家 App):当日营业日 → 抄 4 个数字(开房数 / 时间费合计 / 点单合计 / 签到人数)。
2. **导入**:管理端「双轨对账」页 → 选营业日 → 粘贴/填写四值 → 「导入并比对」。
3. **看结果**:逐指标 `MATCHED`(差=0)或 `OPEN`(差≠0,页面红显差值)。
4. **差异处置**:OPEN 行当场查因(最常见:对侧含店内消费/低消口径、时点取在关房前)→ 次日导修正值并备注(EXPLAINED)。
5. **台账**:连续 14 天全 MATCHED → 满足切换门禁(见 08 号文档 R-1~R-4)。

## 三、API(程序化对账/导出)

```
GET  /api/v1/reports/recon?businessDate=YYYY-MM-DD
     → { rows:[{metric,selfValue,legacyValue,diff,status}], overall, selfMetrics }
POST /api/v1/reports/recon/legacy
     → { businessDate, metrics: { openCount, roomFee, orderTotal, checkedIn } }
POST /api/v1/reports/recon/snapshot          # 手工触发自算快照(日切 job 自动做,首日/补录用)
GET  /api/v1/reports/recon/history?days=14   # 14 天门禁视图
     → { days:[{businessDate,overall,complete,matched,total}], streak, gateDays, gatePassed }
```
`overall = MATCHED | OPEN | NO_DATA | PENDING_LEGACY | EXPLAINED`;`selfMetrics` 恒返回(便于对侧先抄本侧再填对侧)。

**自动化(2026-11-01 起)**:日切 job 每天自动把「上一完整营业日」四指标自算值快照进 recon(PENDING_LEGACY,待录对侧);对侧数字当日录入即出比对。管理端「双轨对账」页顶部为 **14 天门禁面板**(14 格逐日总体色块,点格跳当日;连续一致天数与达标状态实时显示)。注意:若录入对侧后又产生本侧数据(补钟/补结算),快照重算会把该日打回 OPEN——这是真值维护语义,重导对侧修正值即可。

## 四、门禁与切换

- **连续 14 个完整营业日**(按营业日连续,缺口即重计):四指标全 MATCHED;进行中的当日不计入门禁。
- 切换日:对侧停新业务录入(只读保留),本系统成为唯一记账源;对侧保留 1 个月只读回退窗口。
- 任一天出现未闭环差异 → 当日不推进门禁计数,差异台账(EXPLAINED 须写原因)。

## 五、已知口径差异(试点期重点盯)

| 项 | 本系统 | 智慧商家 | 处置 |
|---|---|---|---|
| 时间费 | 方案甲:计入房账,关房结算 | 下钟即扣台费流水 | 按营业日总额对齐即可;逐单时点允许差 |
| 点单 | 销售经理自点单(房账) | 收银/触摸屏/微信多点单 | 总额对齐;明细分布允许差 |
| 未收款 | 负余额红显(允许) | 未收款红显 | 口径一致 |
| 跨天场 | 08:00 班次周期连续累计 | 同 | 一致 |
